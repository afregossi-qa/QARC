# Expert Output Templates

## Purpose
Defines the EXACT structure for all files generated by the QA-Expert-Agent in `1_Expert/`. Every ticket analysis MUST follow these templates regardless of ticket type (feature, bug, tech debt, refactor).

---

## Rules

1. **Always use TC# numbering** in test plans (Area.Number format: 1.1, 1.2, 2.1, etc.)
2. **Always include pre-filled findings** in Notes and General Observations from the analysis phase
3. **Always include blank fields** (`_______________`) in manual_input for QA to fill
4. **Always include checkbox items** (`- [x]` confirmed, `- [ ]` open) in General Observations
5. **Always include the Ticket Overview table** in logic_explanation
6. **Always include Gap Analysis with numbered items** and status markers (Clear, RESOLVED, GAP, RISK, NEW)
7. **Always include Risk Assessment table** in logic_explanation
8. **Always include Test Environment Requirements** and Dependencies tables in test_plan
9. **Flows in manual_input** must have specific observation prompts with blank fields, not generic instructions
10. **Never use step-by-step tables** (Step | Action | Expected Result format) in test_plan — use the TC# table format instead
